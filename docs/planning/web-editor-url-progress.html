The plan — four small moves, no DNS, no new costs

  • ① App learns its new home: build apps/editor with Vite base: "/editor/" for web (desktop/Tauri build keeps /), and make the ~8 hardcoded absolute asset paths (/ort/ wasm, demo images, brand, starter templates, help) base-aware. Sonnet subagent, tests must stay green.
  • ② Landing proxies the path: landing/vercel.json gets rewrites /editor/* → yz-editor-k4x7.vercel.app/editor/* and a redirect /dashboard → /editor (the dashboard IS the app's home screen — one app, two doors).
  • ③ /thanks gets the fallback: new "Can't install it? Use it in your browser" section under the download cards, linking /editor.
  • ④ Deploy + verify for real: editor snapshot redeployed with files under an /editor/ prefix (old root URL 302s there, so existing users keep their saved designs — same origin), landing redeployed, then drive youzign.com/editor, /dashboard and /thanks in headless Chrome with screenshots below.
Why the old URL keeps working: designs live in the browser's local storage, tied to the web address. By keeping the app on the same Vercel project (just under /editor/, with the root redirecting there), the couple of Win7 clients already using it lose nothing.
Trade-off accepted: the obscure URL was the only "access control" — at youzign.com/editor the web app is fully public. Fine by design: the product is free forever.
